# 콘텐츠 리스트 및 구현 로드맵

작성일: 2026-03-08  
기준 문서: `Docs/Reference.md`, 현재 서버 구현(RPC 등록/서비스 코드), 기존 기획 문서

## 1. 선정 기준
다음 기준을 만족하는 항목만 로드맵에 포함했다.

1. 기술 검증과 프로젝트 완성도 향상에 유리한 콘텐츠
2. 게임으로 성립하기 위한 최소 핵심 루프
3. 이미 구현되어 있거나 현재 코드베이스에 자연스럽게 확장 가능한 항목

## 2. 현재 콘텐츠 상태 요약

## 2.1 서버/클라이언트 공통 상태
- 인증/입장 루프: 서버는 실동작 가능 수준, 클라이언트는 기본 플로우 동작 수준
- 왕국(기초): 서버는 핵심 기능 동작, 클라이언트는 플레이/편집 UI 동작
- 월드 스테이지: 서버는 보상 포함 핵심 루프 동작, 클라이언트는 진행/완료 동작
- 가챠: 서버는 비용/결과 반영 동작, 클라이언트는 진입/결과 표시 동작
- 쿠키 성장(기초): 서버는 레벨/승급 동작, 클라이언트는 상세/강화 UI 동작

## 2.2 확장 필요 항목
- 서버: 왕국 생산/건설 대기열 기반 처리, 가챠 감사/검증, 쿠키 확장(스킬/토핑/비스킷)
- 클라이언트: E2E 자동화, 공통 에러 처리, 동기화 검증 UI, 운영 로그 가시성

## 2.3 신규 고난도 콘텐츠 후보
- 실시간 레이드 보스(코옵)
- 공방 제작/건설 대기열 시스템
- 시즌 랭킹 + 리플레이 검증
- 길드(가입/기여/버프/레이드)

## 2.4 개발 정도(완성도) 평가 기준
- `L0` 미착수: 기획만 존재, 코드/화면 없음
- `L1` 프로토타입: 단일 경로 동작, 예외/검증/복구 부족
- `L2` 기능 구현: 핵심 기능은 동작, 엣지케이스/운영성 부족
- `L3` 베타 가능: 핵심 루프 + 기본 검증 + 기본 오류 처리
- `L4` 라이브 준비: 운영 로그/회귀 테스트/복구 전략 확보
- `L5` 운영 안정: 성능/관측성/자동화까지 포함한 안정 운영 가능

## 3. 콘텐츠 로드맵 표

| 기획 이름 | 간단 설명 | 예상 개발 기한 | 서버 개발 정도 | 클라이언트 개발 정도 | 우선순위 | 주요 기술 |
|---|---|---|---|---|---|---|
| 인증/입장 루프 | 회원 식별, 세션 발급, 게임 진입, 초기 닉네임 설정 | 완료 | `L3` 베타 가능(인증/세션/입장 동작, 보안·운영 강화 필요) | `L2` 기능 구현(온보딩 플로우 동작, 오류 복구 미흡) | P0 | 세션 관리, 요청 검증, RPC 게이트 |
| 프로필/플레이어 기초 상태 | 레벨/이름/기본 상태 로드 및 변경 | 완료 | `L2` 기능 구현(기초 상태 처리 완료, 메타 확장 부족) | `L1` 프로토타입(표시 중심, 편집/검증 흐름 약함) | P1 | 상태 모델링, DB 매핑, 동기화 |
| 왕국 건설/배치 기초 | 건물/데코 구매, 배치, 건설 완료, 시간 단축 | 완료 | `L3` 베타 가능(핵심 루프 동작, 데이터 구조 리팩터링 필요) | `L2` 기능 구현(기본 UI 동작, 회귀/동기화 검증 부족) | P0 | 상태 전이, 맵 스냅샷, 트랜잭션 |
| 월드 스테이지 진행/보상 | 스테이지 클리어, 별 갱신, 월드 보상 수령 | 완료 | `L3` 베타 가능(핵심 보상 루프 동작, 예외 케이스 강화 필요) | `L2` 기능 구현(진행/완료 UI 동작, 실패 시나리오 미흡) | P0 | 보상 검증, 멱등 보상 처리 |
| 가챠(기초) | 스케줄 기반 뽑기, 비용 차감, 결과 보상 반영 | 완료 | `L3` 베타 가능(핵심 가챠 동작, 감사로그/검증 고도화 필요) | `L2` 기능 구현(팝업/결과 동작, 이력/재시도 UX 부족) | P0 | 확률 처리, 비용 검증, 재화 정산 |
| 쿠키 성장(레벨/승급) | 쿠키 레벨업/승급 처리 | 완료 | `L2` 기능 구현(레벨/승급 완료, 스킬/장비축 미구현) | `L2` 기능 구현(상세/강화 UI 동작, 확장 시스템 미구현) | P1 | 성장 검증, 재화 소모 정합성 |
| 공방 제작/건설 대기열 | 제작/건설을 줄 세워 처리하고 완료 보상을 수령하는 시스템(취소/가속 포함) | 2~3주 | `L0` 미착수(상세 기획 완료) | `L0` 미착수 | P0 | 대기열 처리, 워커, 시간 보정, 멱등 키, 정산 트랜잭션 |
| 실시간 레이드 보스(코옵) | 2~4인 룸 기반 보스전, 틱 시뮬레이션/재접속 복구 | 3~4주 | `L0` 미착수(상세 기획 완료) | `L0` 미착수 | P1 | 룸 인스턴스, 서버 권위 전투, 스냅샷/복구 |
| 시즌 랭킹 + 리플레이 검증 | 시즌 점수 집계, 랭킹, 서버 재계산 검증 | 2~3주 | `L0` 미착수(상세 기획 완료) | `L0` 미착수 | P1 | Redis SortedSet, 검증 파이프라인, 이상치 탐지 |
| 길드(가입/기여/버프/레이드) | 다중 유저 협업 도메인 + 길드 콘텐츠 | 3~4주 | `L0` 미착수(상세 기획 완료) | `L0` 미착수 | P2 | 분산락, 다중 유저 트랜잭션, 이벤트 알림, 감사 로그 |

## 4. 단계별 구현 계획

주당 최대 8시간 기준으로, 전체를 L2까지 넓히는 방식이 아니라 콘텐츠를 하나씩 `L5`까지 올리는 순차 전략을 사용한다.

## Phase A0 (1~2주) - 공통 기반 최소 세팅
- 목표:
1. 공통 에러코드/검증 규칙 확정
2. 구조화 로그 포맷 확정
3. 테스트 템플릿(단위/통합) 확보
- 서버 작업:
1. 공통 예외/ResultCode 매핑 정리
2. 요청 검증 유틸 표준화
3. 테스트 베이스 클래스/픽스처 작성
- 클라이언트 작업:
1. 공통 에러 메시지 매핑 테이블 정리
2. 요청/응답 로그 패널 기본형 추가
3. E2E 시나리오 실행용 버튼/도구 정리
- 완성 수준 목표:
1. 서버 공통 기반 `L3` 이상
2. 클라이언트 공통 기반 `L2` 이상
3. 기대 상태: 공통 규칙(에러/검증/로그)이 모든 콘텐츠에 재사용 가능하고, 기본 회귀 테스트를 같은 방식으로 반복 실행할 수 있는 상태
- 산출물:
1. 콘텐츠 공통 체크리스트(`L3 -> L4 -> L5`)
2. 최소 회귀 테스트 세트

## Phase A1 (2~3주) - 가챠(기초) `L3 -> L5`
- 목표:
1. 중복 요청/중복 보상 방지 강화
2. 감사 로그/이력 검증 보강
3. 실패 케이스 회귀 테스트 고정
- 서버 작업:
1. 요청 멱등 키 적용
2. 가챠 결과 감사 로그/검증 로직 보강
3. 실패/재시도 케이스 통합 테스트 추가
- 클라이언트 작업:
1. 가챠 재시도/실패 UX 정리
2. 결과 이력 화면/로그 연동
3. 중복 요청 방지 UI 잠금 처리
- 완성 수준 목표:
1. 서버 `L5`
2. 클라이언트 `L3`
3. 기대 상태: 서버는 중복 요청/중복 보상/실패 재시도까지 안정적으로 처리하고, 클라이언트는 실패/재시도 흐름을 사용자에게 일관되게 제공하는 상태

## Phase A2 (2~3주) - 월드 스테이지 `L3 -> L5`
- 목표:
1. 보상/별 갱신 정합성 강화
2. 예외 케이스(반복 클리어/중복 수령) 보강
3. 운영 지표/로그 연결
- 서버 작업:
1. 보상 중복 수령 차단 로직 강화
2. 별 갱신/진행도 검증 강화
3. 월드 진행 지표 로그 추가
- 클라이언트 작업:
1. 실패 케이스 표시(재시도/오류 코드) 보강
2. 월드 진행 상태 동기화 화면 점검
3. 테스트 시나리오 자동화 추가
- 완성 수준 목표:
1. 서버 `L5`
2. 클라이언트 `L3`
3. 기대 상태: 서버는 월드 보상 정합성(중복/누락 없음)을 보장하고, 클라이언트는 진행도/보상 상태를 재접속 후에도 정확히 복원하는 상태

## Phase A3 (2~3주) - 왕국 건설/배치 `L3 -> L5`
- 목표:
1. 상태 전이/스냅샷 정합성 강화
2. 배치/보관/완료 흐름의 복구 시나리오 보강
3. 클라이언트 동기화 검증 시나리오 확장
- 서버 작업:
1. 상태 전이 검증 로직 강화
2. 스냅샷 저장/복구 경계 케이스 보강
3. 배치/보관/완료 트랜잭션 안정화
- 클라이언트 작업:
1. 배치/편집/완료 흐름 동기화 검증
2. 충돌/실패 시 UI 복구 처리
3. 왕국 E2E 회귀 시나리오 강화
- 완성 수준 목표:
1. 서버 `L5`
2. 클라이언트 `L3`
3. 기대 상태: 서버는 왕국 상태 전이와 스냅샷 복구를 안정적으로 보장하고, 클라이언트는 배치/편집 중 오류가 나도 UI 상태를 안전하게 복구하는 상태

## Phase A4 (1~2주) - 인증/입장 `L3 -> L5`
- 목표:
1. 세션 만료/재발급/재진입 경계 강화
2. 인증 실패/재시도 정책 고정
3. 보안/운영 로그 정리
- 서버 작업:
1. 세션 만료/재발급 정책 확정
2. 인증 실패 코드 표준화
3. 인증 감사 로그/추적 강화
- 클라이언트 작업:
1. 재로그인/재진입 UX 정리
2. 인증 실패 시 안내/복구 흐름 정리
3. 로그인 E2E 시나리오 보강
- 완성 수준 목표:
1. 서버 `L5`
2. 클라이언트 `L3`
3. 기대 상태: 서버는 세션 라이프사이클(만료/재발급/재진입)을 일관되게 처리하고, 클라이언트는 인증 오류 시 자동/수동 복구 경로가 명확한 상태

## Phase A5 (2~3주) - 쿠키 성장 `L2 -> L5`
- 목표:
1. 레벨/승급 검증 로직 보강
2. 성장 실패 케이스 회귀 테스트 추가
3. 추후 확장(스킬/장비축) 대비 구조 정리
- 서버 작업:
1. 성장 비용/수치 검증 강화
2. 실패/경계 케이스 테스트 보강
3. 확장 포인트(스킬/장비축) 인터페이스 정리
- 클라이언트 작업:
1. 성장 실패/재시도 UI 처리 보강
2. 성장 결과 반영 검증
3. 쿠키 상세 화면 상태 동기화 안정화
- 완성 수준 목표:
1. 서버 `L4~L5`
2. 클라이언트 `L3`
3. 기대 상태: 서버는 성장 수치/비용 검증과 회귀 테스트가 갖춰져 신규 확장(스킬/장비축) 준비가 된 상태이며, 클라이언트는 성장 결과를 안정적으로 반영하는 상태

## Phase B (2~3주) - 공방 제작/건설 대기열 `L0 -> L3`
- 목표:
1. 제작 시작/완료/수령 1차 루프 구현
2. 취소/가속 핵심 동작 구현
3. 대기열/시간 보정 기초 안정화
- 서버 작업:
1. 제작 시작/완료/수령 API 구현
2. 취소/가속/일괄 수령 처리
3. 대기열 워커 + 시간 보정 기초 적용
- 클라이언트 작업:
1. 대기열 UI(남은시간/순번/완료상태) 구현
2. 취소/가속/일괄 수령 UX 구현
3. 오프라인 복귀 시 상태 반영 확인
- 완성 수준 목표:
1. 서버 `L3`
2. 클라이언트 `L2~L3`
3. 기대 상태: 제작/건설 대기열의 핵심 루프(시작-완료-수령-취소-가속)가 실제 플레이 가능한 수준으로 동작하고, 기본 예외 처리가 가능한 상태

## Phase C (확장, 6~10주) - 고난도 콘텐츠 순차 구현
- 순서:
1. 실시간 레이드 보스 `L0 -> L3`
2. 시즌 랭킹 + 리플레이 검증 `L0 -> L3`
3. 길드(가입/기여/버프/레이드) `L0 -> L3`
- 원칙:
1. 각 콘텐츠는 `L3` 달성 후 다음 콘텐츠로 이동
2. 이후 다시 순차적으로 `L3 -> L5` 승급
- 서버 작업:
1. 레이드 룸/틱/스냅샷 구현
2. 시즌 랭킹 집계/검증 파이프라인 구현
3. 길드 도메인(가입/기여/버프/레이드) 구현
- 클라이언트 작업:
1. 레이드 입장/전투/결과 UI 구현
2. 시즌 랭킹/보상 화면 구현
3. 길드 기본 화면(가입/기여/레이드) 구현
- 완성 수준 목표:
1. 각 신규 콘텐츠 1차 목표: 서버 `L3`, 클라이언트 `L2~L3`
2. 2차 목표: 순차적으로 서버 `L5`, 클라이언트 `L4`까지 승급
3. 기대 상태: 1차는 플레이 가능한 핵심 루프 확보, 2차는 운영 지표/회귀 테스트/장애 복구까지 포함한 안정 운영 수준 달성
