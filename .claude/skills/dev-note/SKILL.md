## 작업 순서

1. 오늘 날짜를 `YYYY-MM-DD` 형식으로 확인한다.
2. 오늘 커밋이 없으면 "오늘 커밋이 없습니다." 안내 후 중단한다.
3. **당일 기존 노트가 있는지 확인한다.**
   - 있으면: 기존 파일을 그대로 유지하고, 기존 커밋 테이블에 이미 기록된 커밋을 제외한 **새 커밋만** 항목으로 추가 작성한다. 파일명도 기존 파일명을 그대로 사용한다.
   - 없으면: 아래 순서대로 새 파일을 만든다.
4. 하루 전체 커밋을 통합해 큰 흐름으로 파악한다. 커밋 단위가 아닌 **의미 단위**로 판단해 작성한다:
   - 주요 항목이 하나면 단일 단락으로 통합 서술
   - 주제가 명확히 다른 항목이 여럿이면 `## 1.`, `## 2.` 형식으로 분리
5. **파일명**을 결정한다 (신규 파일인 경우):
   - 형식: `YYYYMMDD_주제1_주제2.md` (기존 파일명 패턴 참고)
   - 주제는 영문 소문자 + 언더스코어, 핵심 키워드 1~2개
   - 예: `20260310_gacha_idempotency.md`, `20260310_kingdom_queue.md`
6. **노트 내용**을 작성한다 (아래 형식 준수):

### 노트 작성 형식

`$ARGUMENTS`가 비어있지 않으면 제목 바로 아래에 느낀점 섹션을 추가한다. 비어있으면 해당 섹션을 생략한다.

```markdown
# YYYY-MM-DD 개발 노트

> 💬 $ARGUMENTS

<!-- $ARGUMENTS가 없으면 위 줄 전체 생략 -->

[단일 주제인 경우 — 통합 단락으로 서술:
오늘 무엇을 왜 했는지 큰 흐름 위주로 서술. 배경(문제/목표) → 한 일 → 결과 순서로 5~10줄 이내.
중요한 기술적 결정이나 주의사항이 있으면 `> **핵심 포인트**:` 로 강조.]

<!-- 주제가 여럿인 경우 아래처럼 항목 분리 -->
## 1. [항목 제목 — 한 줄 요약]

[설명]

> **핵심 포인트**: [...]

## 2. [항목 제목]

[설명]

![{변경된 화면/기능 캡처}](./img/YYYY-MM-DD_1.png)
<!-- 이미지: [어떤 화면이나 동작을 캡처하면 좋은지 구체적으로 설명] -->

---

*이 노트는 아래 커밋을 바탕으로 AI(Claude)가 작성했습니다.*

| 커밋 | 메시지 |
|------|--------|
[커밋 목록을 `| \`hash\` | 메시지 |` 형식으로 한 행씩 채운다]
```

### 이미지 플레이스홀더 삽입 기준

다음 경우에 `![...](./img/YYYY-MM-DD_N.png)` 플레이스홀더를 삽입한다:
- UI 화면이 추가되거나 레이아웃이 변경된 경우
- 새로운 게임 기능이 인게임에서 눈에 보이는 경우
- 데이터 흐름이나 시스템 구조를 다이어그램으로 보여주면 이해가 쉬운 경우
- 버그 수정 전/후 비교가 필요한 경우

서버 내부 로직만 변경(DB 쿼리 최적화, 에러 코드 정리 등)된 경우 이미지 불필요.

이미지 번호는 같은 날짜 내에서 1부터 순서대로 부여한다.

### 완성 후

7. 완성된 파일을 `Docs/DevelopNote/{파일명}.md` 경로에 저장한다.
   - 기존 파일에 추가하는 경우: 기존 커밋 테이블 행에 새 커밋을 **추가**하고, 새 항목 섹션을 맨 아래(커밋 테이블 위)에 이어 붙인다.
8. 저장 후 파일 경로와 함께 "이미지 플레이스홀더 N개 삽입됨 — 직접 채워넣으세요." 안내한다.

## 작성 스타일 가이드
- 독자 수준: 이 프로젝트를 처음 보는 개발자
- 문체: 간결하고 친절한 한국어. 불필요한 경어 없이 명확하게.
- 길이: 변경 항목당 3~6줄. 너무 길면 핵심만 남긴다.
- 코드 스니펫: 중요한 API명, 클래스명, 메서드명은 인라인 코드(`)로 표시
- TODO 사항이 커밋 메시지나 코드에 있으면 노트 하단에 `## 남은 작업` 섹션으로 모아준다
